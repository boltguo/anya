# aouo 短视频矩阵与运营策略 (Short Video Strategy)

> 📌 **品牌迁移说明**：项目原名 `Anya`（《间谍过家家》角色名，开源有版权风险），已重命名为 `aouo`。
>
> **资产清单**（详见 [`launch-plan.md` §1](launch-plan.md)）：
> - 产品 / 品牌：`aouo`
> - 域名：`aouoai.com` ✅ + `aouo.ai` ✅
> - npm scope：`@aouo` ✅
> - GitHub：`github.com/aouoai` ✅
> - 抖音 / 视频号 / 小红书 / B 站 / TikTok / YouTube：`aouoai` ✅
> - X / Twitter：`@aouo_ai` ✅（与主域名 `aouo.ai` 对齐）
> - Agent 角色名：`aouo` 自身 ✅
>
> **相关文档**：[`pack-architecture.md`](pack-architecture.md) 技术 RFC、[`launch-plan.md`](launch-plan.md) 上线节奏

这份文档规划 aouo Agent 的短视频运营路径——目标是把一个长期打磨的个人项目转化为有影响力的产品/IP。

**项目家底先报一遍**（视频里要打字幕反复曝光这些数字）：

- **29 个 skill 体系化沉淀**（27 个英语训练 skill + 2 个 support 数据契约）——覆盖听 / 说 / 读 / 写 / 词 5 大方向
- **12 个底层 tool**（persist / cron / tts / pronAssess / telegram / memory / db / skill / clarify / file / webSearch / registry）——不是 prompt 拼接，是真正的工具调用框架
- **~12,000 行 TypeScript**，模块化分层：agent / adapters / providers / tools / skills / storage / domain
- **持续打磨数月**，从基础聊天机器人迭代成有数据库、有 SRS、有 cron、有 placement 评估的完整学习闭环
- **自研 agent 主循环 + 上下文压缩 + 数据契约**——为这一份个人助手定制，不通用

> ⚠️ **项目阶段诚实声明**（必须先在这里讲清，下面才能立得住）
>
> aouo **当前是一个个人助手原型，重构 + 解耦中**。原因：
> 1. **代码债存在**——快速迭代痕迹没擦干净，作为 v1 personal 工具能跑，作为开源项目还远没到 production grade
> 2. **agent 主循环和英语 skill 强耦合**——多 domain 复用是设计意图，但**目前没解耦**。未来要拓展到日语 / 健身才会逼出干净抽象层
> 3. **作为个人 IP 项目，"产品 = 内容 + 方法论 + 陪伴"**，不是"产品 = 代码"
>
> 这意味着——**整个内容矩阵的输出物是「方法论」与「使用故事」，不是「代码仓库」**。CTA 不指向 GitHub，指向内测群 / 关注 / 知识付费 / 咨询。

**核心运营策略**：用一条 Flagship 视频引爆破圈，再用系列拆解承接流量。**先把"一周使用 vlog"作为 ep1 把人钩进来**，再用方法论拆解的 ep2–8 把人留下来——每集都回扣 §1.3 的"为什么框架 + skills 替代不了"护城河论证。

> ⚡ 节奏说明：原计划积累 30 天素材，但拖太久会错过窗口期。本版方案改为 **5–7 天最小可用素材**——靠"密集使用 + 真实场景"撑起 ep1 的可信度。系统本身的深度（数月迭代 + 29 skill）作为**可信度兜底**反复曝光。

## 1. 核心 Thesis：Domain Companion（这是整个系列的灵魂论点）

> 整个内容矩阵的 thesis 必须先讲清——**不是"我做了个英语 app"**，而是：
>
> **aouo 是 "Domain Companion" 这一新型 agent 形态的早期样本**——介于通用 agent 框架与浅层 AI 应用之间，市场上长期缺少成熟样本。

### 1.1 Agent 的三层坐标

| 层级 | 代表 | 形态 | 局限 |
| --- | --- | --- | --- |
| 通用 Agent 框架 | Hermes / Claude Agent SDK / LangGraph | 给开发者搭 agent 的工具 | 任何具体领域都不深 |
| **Domain Companion（aouo 在这）** | aouo（英语 / 健身 / 理财 / ……每个 domain 一个 pack） | 一个 domain 的长程陪伴 agent | 不通用，迁移要重写 SKILL.md |
| 浅层 AI 应用 | GPT 套壳 / Prompt 拼接 | 一次性对话工具 | 没记忆、没主动、没数据闭环 |

### 1.2 Domain Companion 的五要素（缺一不可）

1. **长记忆**：用户画像月级累积，不是一次性 conversation memory
2. **主动触达**：cron / 心跳 / 推送，"它来找你"，不是你打开 app
3. **多 skill 体系**：一个 domain 至少 10+ 个细分技能（aouo 当前 27 个英语 skill）
4. **数据闭环**：练习入库 → 弱项加权 → 下次出题，每次使用都让画像更准
5. **领域内置评估**：CEFR 这种标尺嵌进去，系统知道"你现在 B1，距 B2 还差什么"

少一样，掉到浅层 AI 应用层。这是**定义性边界**。

### 1.3 为什么 Hermes / OpenClaude / LangGraph + skills 替代不了（最关键的护城河论证）

视频评论区**必然出现**的质疑："你这套不就是 agent 框架 + 一堆 skills 吗？我用 Hermes 写几个 skill 也能做。"

错。**Domain Companion 的真正难点不在 skill 写得多好，在 skill 之下两条基础设施必须和 skill 联合演进**：

#### (1) DB-as-Behavior，不是 DB-as-Storage

通用框架的"记忆"是临时 conversation history，或泛 KV / vector store。aouo 不是。

- 每次练习入 `samples` 表，schema 含 `subcap_scores` / `errors[]` / `metadata`——**所有 skill 共用一份强 schema 数据契约**
- learner-state 跨 skill 聚合：写作的从句错误能让阅读 skill 下次刻意挑同类
- SRS 状态机（mastery: queued_new → weak → shaky → mastered）在 **DB 层**运行，不是 skill 层
- EMA 持续矫正：`α = min(0.6, n/10)`——**DB 字段直接驱动 agent 决策**

通用框架里写 skill 的人**不拥有 DB schema 设计权**——框架给你一个泛 memory store，你只能往里塞，没法让 agent 行为基于"结构化跨 skill 聚合"发生改变。

#### (2) UX 适配器与 agent 主循环必须共设计

通用框架的输出层是 `send_message(text)`。aouo 的不是。

- Telegram 的 inline keyboard / callback query / force_reply / spoiler / 语音 / edit / 多页菜单——是**交互原语**，不是简单输出
- 用户点「太难了」→ adapter 解析 callback → agent state 知道当前 skill 是 listening-dictation 第二轮 → persist 一条 `completed=0` 行 → 生成更简单的下一题——这个回路跨 (skill 状态) × (TG callback) × (DB schema) 三层
- 「single-call tg_msg with keyboard」是 adapter 层的 runtime 强制约束，避免 LLM 先发文字再 edit 加按钮——**通用框架的 skill 抽象表达不了这种约束**

#### 结论

> **Skills 是冰山尖，水下是 DB schema + 适配器协同。**
>
> 在 Hermes 里写 skill 复刻 Domain Companion 的尝试会撞墙——不是 skill 不够好，是水下两层不归 skill 作者管。这才是中间层真正不可替代的护城河。

这就是 ep2-7 必须反复打透的核心点——**讲完工程亮点，最后一定回扣这句论证**。

### 1.4 方法论可移植 = thesis 的内容引擎（不是代码可移植）

**重要诚实**：当前 agent 主循环和英语 skill 是耦合的，不能"换 SKILL.md 立刻教日语"。所以多 domain 不能拍成"代码 fork demo"，要拍成 **"方法论应用"**：

- 「我下一步要把这套方法用到日语——拆解前先讲清要动哪三层（DB schema / skill 集 / adapter 行为）」
- 「我研究了 6 个月得到的 5 要素 checklist——你想做自己的 Domain Companion，先对照这张表」
- 「同一套五要素用在英语 → 用在健身要怎么改 SRS 状态机」（改写成"思考实验"+ 部分原型，不强行说"已经做好了"）

**每开一个新 domain（哪怕只是设计文档级），都是「Domain Companion 五要素方法论确实可移植」的现场证明。** 输出物是**思维框架 + 设计经验**，不是 fork-and-run 代码。这反而是更高密度的内容——开源项目能给代码，方法论给的是判断力。

> 副产品：**"我接下来要拓 domain，会先解耦"**这个过程本身就是连续短视频素材——「重构日记」类型，开发者爱看。

## 2. 受众与单条视频策略

aouo 同时具备「硬核技术底座」与「高频实用场景」，对应两类完全不同的受众：

1. **英语学习者 (To C)**：关心"能不能帮我克服哑巴英语 / 提分"，不关心代码。
2. **极客 / 开发者 (To D)**：关心"Domain Companion 这层是怎么实现的"，讨厌营销话术。

**单条视频不能同时讨好两边**——主路径打 To C（流量池大两个数量级），开发者钩子靠 ep1 末尾的伏笔 + ep2+ 的架构篇 + §1.3 护城河论证承接。

## 3. 项目身份与差异化（必须打出去的牌）

这一节是**所有视频的弹药库**。每条视频至少明显曝光 2–3 个特点，让观众反复确认"这不是周末项目，是一套真东西"。也是 §1.3 护城河论证的具体素材来源。

### 3.1 学习闭环（学习者向卖点）

- **多模态全覆盖**：语音输入（ASR）+ 语音输出（TTS）+ 文字 + 内联键盘按钮 + 隐藏剧透标签——不止是"能聊天"
- **29 个细分技能模块**，每个 skill 自己的状态机和评分规则：
  - 听力：句子精听 / 意群跟读 / 数字捕捉 / 播客泛听
  - 口语：发音矫正 / 听后复述 / 自由闲聊 / 情景对话 / Azure 评分
  - 阅读：外刊精读 / 快速略读 / 话题讨论 / 打字训练
  - 写作：句型搭建 / 升级改写 / 日记碎碎念 / 综合长文
  - 词汇：到期复习 / 话题词汇 / 抽查测验 / 自动归档
  - 评估：placement-quick 五维定级 + learner-state 持久画像
- **CEFR 子带定级**：不是粗糙的"初/中/高"，而是 A2- / A2 / A2+ / B1- / B1 / B1+ / B2- … / C1+ 的 12 级颗粒度
- **错题不是清单是闭环**：每次练习入 `samples` 表 + 错误 key 归类（collocation_error / register_mismatch / paraphrase_miss…），下次出题自动加权
- **SRS 间隔重复**：自研 ease / interval / mastery 状态机（queued_new → weak → shaky → mastered），不是简单的"每天重放"
- **置信度可见**：每次评分都带 confidence（low/med/high），系统自己知道"我没把握"，不会硬给你乱评

### 3.2 主动陪伴（"它来找你"）

- **Cron 主动触达**：早 8 点早读、晚 9 点复习、周末错题回顾——你不打开 Telegram，它会推你
- **JSON 驱动的轻量定时**：不依赖 Celery / Redis，60 秒心跳即可调度
- **大模型自己写 cron**：语音说"以后每天下班提醒我复习语法"，后台 JSON 自动更新
- **EMA 持续矫正**：练得越多，画像越准；α = min(0.6, n/10) 让画像有惯性，不会一次糟糕练习就崩
- **Autonomous loops**：可在指定时间自唤醒继续上次的工作

### 3.3 工程硬核（开发者向卖点）

> 注：这一节的所有点都是"已经在跑、能演"的事实，但**不能拍成"完美工程展示"**——代码债存在，主循环和英语耦合是公开承认的现状。讲的是"为这一份个人助手做对了什么"，不是"通用框架最佳实践"。

- **自研 Agent 主循环**：Agent.ts 主循环 + 工具注册中心 + 上下文压缩，不依赖 LangChain / LangGraph，但承认主循环和英语 skill 当前是耦合的——**这是为单 domain 跑稳定做的工程取舍**
- **统一的 `tg_msg` 工具**：所有发消息收敛到一个 single-call 入口，强制大模型不能"先发文字再 edit 加按钮"
- **滑动窗口上下文压缩**：保护头尾、压缩中段、保留 sent-text preview——长会话不失忆，账单可控
- **严格的 persist 数据契约**：每个 skill 有 schema，subcap_scores / errors[] / metadata 强 schema 约束，跨 skill 数据可聚合
- **TypeScript 强类型**：把含糊的聊天强制转成结构化数据，从根源上拒绝"prompt 套壳"
- **Skill 文件即配置**：每个 skill 一个 SKILL.md + 模板目录，热加载 menu.json，零运维上新 skill
- **三层可观测**：agentLogger 结构化日志 + tg_bare_text_fallback 警告 + 每条 sample 入库——bug 发生时一定能复盘

### 3.4 Skill 质量闭环（每个 skill 都被"测过、验过、调过"）

这一点非常重要，**和"功能多"是两回事**——是"功能可靠"。视频里要专门打一节。

- **真实会话日志驱动的迭代**：每一次练习都进 `samples` 表 + 结构化日志（agentLogger）。系统跑出 bug、评分不准、用户体感不对——回看 log 一定能找到根因
- **Skill 规则迭代历史可追溯**：每个 SKILL.md 都经过多轮调整（例：placement-quick 的 Reading 评分一开始把"理解"和"表达"混在一起，用户实测后拆成两维；listening-dictation 的 credit gating 经过多轮 PASS/FAIL 阈值调优）
- **Token 成本持续优化**：[`docs/token_optimization_analysis.md`](docs/token_optimization_analysis.md) 是专门的成本分析文档——上下文压缩、工具收敛、SKILL.md 瘦身（287 行 → 165 行的精听 skill 压缩计划）每轮都量化
- **数据契约 = 跨 skill 一致性测试**：所有 skill 写 `samples` 必须符合 persist schema（subcap_scores / errors[] / metadata），任何一个 skill 漏字段都会让 learner-state 聚合崩——这本身就是约束式测试
- **Vitest 单测脚手架已就位**（`npm test`），核心 helper（contextCompressor / accuracy 计算 / SRS 状态机）覆盖中
- **bug 出了就加防御层**：例如 LLM 偶发返回 bare text 不调 `tg_msg`——加了 `tg_bare_text_fallback` warning log + KEEP_RECENT_TOOL_RESULTS 6→8 + sent-text preview 三层防御，每个都有具体来源

### 3.5 反"周末项目"信号清单（视频里要反复打这些字幕）

- ✅ 持续打磨数月（不是周末黑客松）
- ✅ ~12,000 行 TypeScript
- ✅ 29 个 skill / 12 个 tool
- ✅ 数据库 schema 经过 N 轮迭代（看 git history）
- ✅ 上下文压缩 / 工具收敛 / 数据契约都是踩坑后的产物，每个有"为什么这么做"的故事
- ✅ 每个 skill 都经过真实使用反复调优——评分规则不是拍脑袋，是被实测打脸后改的
- ✅ Token 成本有专门分析文档持续优化

> 同时**坦诚承认**（自爆比被扒强）：
>
> - ⚠️ 当前是 personal prototype，不开源——代码债没擦干净
> - ⚠️ Agent 主循环和英语 skill 耦合，多 domain 复用是设计意图但**还没解耦**
> - ⚠️ Vitest 脚手架在，但单测覆盖还不充分
>
> **这两组信号同时打**：第一组建立"做了真东西"的可信度，第二组建立"这个人不装"的人格魅力。两个加起来 = 完整 IP 形象。

## 4. Flagship 系列规划 (主推路径)

### 4.1 Ep1：「我和我的 AI 私教的一周」 (90s 一周浓缩 vlog)

**定位**：不要拍功能清单，拍真实使用流程的浓缩 + 系统深度的硬实锤。

**Hook (0–3s)**：
直接屏幕录像。Telegram 凌晨 2 点弹推送：
> "还记得你 4 天前把 'elaborate about' 写错了吗？今天再来一次。"

字幕：「凌晨两点，我的 AI 老师翻出了我几天前的错题。打磨数月的赛博英语私教。」

**Body 分镜 (3–75s)**：

| 时间 | 场景 | 功能曝光 | 角标字幕 | 素材门槛 |
| --- | --- | --- | --- | --- |
| 3–10s | 文件树 + skill 列表一闪而过 | 项目深度 | "29 个 skill / 12,000 行 TS" | 立即可拍 |
| 10–22s | 早 8 点 cron 主动推送早读 + 复习清单 | Cron 主动触达 | "60 秒心跳调度，AI 自己写定时" | Day 2 起 |
| 22–35s | 通勤路上语音 freetalk，秒回 native 表达 + 标错 | 语音对话 / 实时纠错 | "ASR + TTS 全语音流" | Day 1 |
| 35–50s | 一键「加入生词本」，AI 翻出 Day 1 错过的同一个词 | SRS / 长记忆 | "queued_new → weak → mastered" | Day 4+ |
| 50–62s | 午休丢一段外刊，AI 拆句 + 自动归档错题 | 阅读精读 / 错题归类 | "collocation_error / register_mismatch 自动 tag" | Day 1 |
| 62–75s | 睡前日记 + 雷达图截图（Day 1 vs Day 7） | 评估画像 | "CEFR 12 级子带定级" | Day 1 + Day 7 |

**揭秘 + CTA (75–90s)**：
> "它不是聊天机器人——是 12,000 行 TypeScript、29 个 skill、打磨数月的私教系统。
> 暂时不开源（代码债没擦干净，先稳定自用），想试的扣 1，发你内测群。
> 你可能觉得这就是 ChatGPT 套壳——下一期我讲讲为什么 ChatGPT 加了 memory 也做不到这件事。"

**关键约束**：
- 时长 ≤ 90s（抖音/小红书）。B 站可剪 5–8min 扩展版同源发。
- 钩子必须**显式**——"下一期讲什么"要说出来。
- **角标字幕反复打深度**：每个场景至少一条"硬核数据"角标（行数 / skill 数 / 算法名 / 月数）。
- **素材积累目标**：1 周内每天 ≥ 30min 真实使用，覆盖 5 个核心场景。
- 若一周内雷达图变化不显著，**改用「新增掌握词数」「连续打卡天数」「错题归档数量」**——比小幅雷达图更有冲击力。

### 4.2 Ep2–7：架构拆解 (每期一个子系统，回扣 ep1 场景 + §1.3 护城河论证)

每集开头先回放 ep1 的相关 cut，再切入"它是怎么做到的"——形成"先看现象、再看原理"的连贯叙事。

| 集 | 主题 | 回扣 ep1 场景 | 回扣 §1.3 护城河 | 平台 |
| --- | --- | --- | --- | --- |
| Ep2 | Cron 心跳 + JSON 驱动 + 大模型自己写定时 | 早 8 点主动推送 | "主动性"原语在通用框架不是 first-class | B 站主发，抖音 60s 切片 |
| Ep3 | SRS 间隔重复 + persist 数据契约 + mastery 状态机 | 翻出几天前的错词 | DB-as-Behavior：不拥有 schema 写不出 SRS | B 站主发，小红书科普切片 |
| Ep4 | 上下文压缩 + 滑动窗口 + sent-text preview 保留 | 聊一周不失忆 / 账单可控 | runtime 约束是 adapter 层的事，skill 写不进去 | B 站主发，Twitter 英文 thread |
| Ep5 | 多 skill 路由 + ReAct 状态机 + 统一 tg_msg | 同一对话切听写 / 精读 / 词汇 | UX 适配器与 agent 主循环必须共设计 | B 站主发，开发者社区分发 |
| Ep6 | placement-quick 4-bucket signal + EMA 矫正 | 雷达图怎么算出来的 | 评估体系嵌进 DB schema，不是 skill 输出 | B 站主发 |
| Ep7 | Skill 质量闭环：日志 → 复盘 → 评分规则迭代 | 「同一对话从评不准到评得准」时间线 | 跨 skill schema 一致性 = 能 log-driven 改 prompt | B 站主发，开发者向 |
| Ep8 (终篇) | **Domain Companion 是什么 / 为什么 framework + skills 替代不了** | 全系列回顾 | §1.3 整段论证完整版 | B 站主发，是开发者圈传播主弹药 |

**每集结构 (5–8min)**：
1. 回放 ep1 现象 (30s)
2. 痛点：传统方案为什么不行 (1min)
3. 实现：核心代码 + 设计图 (3–5min)
4. **回扣护城河**：这一块为什么在 Hermes/LangGraph 里写 skill 复刻不了 (30–60s) ← 这条不能省
5. 钩子：下集预告 + GitHub Star CTA (30s)

## 5. 备用选题池 (横向短条 / 弹药库)

Flagship 系列覆盖不到的角度，做成 30–60s 单条横向投放，用于持续曝光。来自旧版本文档的高潜力选题已收编。

### 5.1 学习者向 (抖音 / 小红书)

- **「不要再花一万块请雅思私教」**：左侧人在喝咖啡，右侧屏幕语音聊天 + 实时纠错。卖点：没有情绪内耗 + 7×24。
- **「ChatGPT 教不会你英语，因为它会失忆」**：对比 demo——同样的错词，ChatGPT 全新对话 vs aouo 翻出几天前的同一句。
- **「凌晨 8 点的赛博连麦」**：纯 cron 主动推送场景剪辑。
- **「英语雷达图怎么算出来的」**：placement-quick 5 维评估流程 + CEFR 子带科普。
- **「AI 私教也有错题本」**：错题归类截图 + 第二天加权出题 demo。

### 5.2 开发者向 (B 站 / Twitter)

- **「手搓 ReAct Agent 主循环，拒绝 Prompt 套壳」**：高亮主循环 + 工具注册中心。
- **「让大模型自己写 Cron 是什么体验」**：语音指令 → JSON 自动更新 → 守护进程触发。
- **「上下文压缩算法实战」**：滑动窗口 + 头尾保护 + sent-text 保留示意图，API 账单对比。
- **「29 个 skill 怎么管理不爆炸」**：SKILL.md + 数据契约 + 热加载 menu.json。
- **「TypeScript 怎么强约束 LLM 输出」**：从含糊聊天到结构化数据的 schema 演进。
- **「我是怎么调出靠谱评分规则的」**：实战案例——placement-quick 一次评分跑偏 → 回查 log → SKILL.md 拆维度修复 → 验证。把"用日志反推 prompt 缺陷"的真实工程过程拍出来，开发者会爱死。
- **「Skill 这么多怎么测」**：data-contract 当 spec、Vitest 覆盖核心 helper、log-driven 复盘——讲软件质量观。
- **⭐「为什么我不开源（坦诚向）」**：30–60s 直接讲——代码债 / 主循环和英语耦合 / 当前是个人原型不是 production——**这条会跑流量**。开发者圈最讨厌假装完美的项目，反向操作"承认不完美 + 讲清楚阶段"反而立得住。
- **「Domain Companion 五要素 checklist」**：纯方法论分享，零代码——给想做自己 AI 助手的人一张可对照的设计清单。免代码 = 免争议 = 易传播。

## 6. 视觉与文案原则

1. **实操感优先**：屏幕必须展示真实交互（清晰的 Telegram 聊天 / 整洁代码块），不要 PPT 配音。
2. **前 3 秒抛痛点**："还在花钱请外教？" / "AI 聊完就忘怎么办？"——不拖泥带水。
3. **拒绝功能清单**："这个 AI 能做 X/Y/Z/W"是 ep1 的死亡公式。一律改成场景叙事。
4. **角标字幕打深度**：每个场景至少 1 条"硬核数字"角标——12,000 行 / 29 skill / 12 tool / 数月迭代。重复打，让"这不是周末项目"变成肌肉记忆。
5. **钩子显式**：每条视频结尾必须有一个明确动作（评论扣 1 / Star / 看下一集）。一条视频一个 CTA。
6. **时长红线**：抖音/小红书 ≤ 90s；B 站架构篇 5–8min；超过的不发短平台。
7. **数字优先于体感**：素材积累不足时，用"新增掌握 X 个词 / 连续打卡 N 天 / 归档 M 个错题"替代"我感觉进步了"——硬数字屏蔽信任成本。

## 8. 流量承接与转化（不开源版本）

> ⚠️ 项目**当前不开源**，所以承接和变现路径都不依赖 GitHub Star / PR。

- **内测群（核心承接）**：评论扣 1 → 私信发群链接，沉淀第一批铁杆用户。这是冷启动唯一通路。
- **关注 + 等待列表**：抖音/小红书引导关注；B 站引导"加入观察 Domain Companion 实验"邮件列表（用 Tally / Notion 表单收邮箱即可）。
- **钉子评论**：提前剪一个 15s「数据库 + Cron + SRS + 12000 行 TS」四连截图，手动置顶反"套壳"杠精——同时附一句"暂不开源，想体验扣 1"避免代码贩子骚扰。
- **数据 KPI**：首发追**完播率 + 评论数 + 内测群入群人数**——证明叙事钩住了人。**Star 数不再是 KPI**。
- **变现路径（候选，不互斥）**：
  1. **SaaS 托管版**：内测群验证后，开放付费托管（每月 ¥99 / ¥199 起）——不卖代码，卖跑起来的服务
  2. **知识付费**：Domain Companion 方法论课程 / 系列文章付费墙——这条是不开源带来的反向红利
  3. **B 端咨询**：帮企业搭垂直 agent 的咨询工时——视频本身就是案例集
  4. **私享圈**：99 元/年深度社群，进群有方法论文档 + 月度直播 + 优先内测
- **诚实优势**：不开源 → 用户从一开始就预期付费 / 关注，**比"开源后再转付费"的转化路径更顺**。

## 10. 风险与红线

- **半年不更新架构篇 = 第一批订阅跑光**。如果 ep2 还没准备好，宁可先压 ep1 的发布。
- **功能清单式叙事 = 死亡公式**。哪怕只有 60s，也要有"一周的故事"或"一个具体场景"，不要"它能做 A、B、C、D"。
- **一周素材的可信度边界**：不要假装"练了一个月"。视频里时间戳就是几天前 → 几天后，更真实。撒谎被扒会反噬。但**系统迭代时长可以也应该说**——"打磨数月的系统"是事实，要打出去。
- **CTA 多动作 = 没动作**。一条视频只能要观众做一件事。
- **雷达图变化不够明显时，不要硬上**——直接换硬数字（词数 / 打卡 / 错题数），可信度更高。
- **硬核字幕不能堆砌成弹幕**——每个场景 1 条就够，不要塞满屏。让数字"被瞄到"，不是"被读完"。
- **§1.3 护城河论证不能讲成"我比 Hermes 强"**——会得罪通用框架社区。正确姿势："Hermes 适合搭通用 agent，Domain Companion 是不同的应用层，需要 DB + adapter 联合设计——不是谁强谁弱的问题，是分工问题。"
- **多 domain demo 不能假装"已经能跑"**——目前主循环和英语耦合，硬演会被扒。讲"接下来要拆"或"如果要拓 domain 设计是这样"，比强行 demo 更稳。
- **不要变成"agent 框架对喷视频"**——重点始终是"Domain Companion 这一层应该被认真对待"，不是踩谁。
- **不开源的可信度风险**：评论区一定有人喷"不开源就是不行"。**预防性自爆**比被动反驳强 10 倍——主动拍一条「为什么我不开源」短条放评论区置顶，把"代码债 / 主循环耦合 / personal prototype"全摊开。坦诚是最强的护城河。
- **没有 Star 数后，KPI 要重定**——不要再盯 GitHub Star，盯**完播率 + 内测群人数 + 等待列表邮箱数 + 付费意愿调查回收率**。这些数字不漂亮但更真实。
- **变现要在 ep1 之前确定主路径**——SaaS / 知识付费 / 私享圈，至少**主押一个**。粉丝起来之后再想路径就晚了。
